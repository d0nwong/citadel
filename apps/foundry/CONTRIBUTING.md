# Contributing

## Running the local stack

First time on a clone: `foundry setup` (see the README's "Setup" section) does
credential, forge image, web deps, infra and schema in one idempotent pass.

From citadel's root:

```sh
just up postgres       # postgres on localhost:5432, waits until healthy
just migrate     # apply the app schema (web/src/db/migrations)
just foundry        # http://localhost:3777
```

`just up postgres` only needs to be run once per session (or after `just down`); rerun
`just migrate` whenever new migrations land. See the README's "Local infra" section
and `web/README.md` for connection details and troubleshooting.

## Branch naming

Branches follow one of two patterns:

- `<username>/<ticket-id>-<short-description>` for work tied to a tracked ticket,
  e.g. `yickkiuleung/lia-11-setup-database`.
- `<type>/<short-description>` for untracked work, where `<type>` is `feat`, `fix`,
  or similar, e.g. `feat/repo-selection`, `fix/restore-mobile-responsive`.

Keep the description short and kebab-case. Open a PR against the current main
branch when ready for review.

`foundry/*` branches are auto-generated by the web UI's job pipeline — don't
hand-author branches under that prefix.

## Commit conventions

Commits follow [Conventional Commits](https://www.conventionalcommits.org/):
`type(scope): summary`, imperative mood, lowercase. This isn't cosmetic —
[release-please](.github/workflows/release-please.yml) parses commit messages on
`main` to decide the next version and write `CHANGELOG.md`.

- `feat` — new capability → **minor** bump, listed under *Features*
- `fix` — bug fix → **patch** bump, listed under *Bug Fixes*
- `feat!:` / `fix!:` or a `BREAKING CHANGE:` footer → **major** bump
- `docs`, `chore`, `refactor`, `test`, `ci`, `build`, `perf`, `style` — no bump,
  hidden from the changelog

Scope is optional; use the area you touched — `web`, `infra` are the ones in use
(e.g. `feat(web): …`, `fix(infra): …`). Root-level or cross-cutting changes can
omit the scope.

To force a specific version, add a `Release-As: x.y.z` footer to the commit.

## Pull requests

- **Title**: a Conventional Commit, same rules as above — CI enforces this. The PR
  title is the source of truth for the changelog, so it must be right even when
  the branch commits aren't (agent-generated `foundry/*` branches, for instance,
  carry raw prompt text as commit messages).
- **Description**: follow the [PR template](.github/PULL_REQUEST_TEMPLATE.md) —
  link the Linear ticket (`Closes LIA-…`), summarize what and why, and say how
  you verified it.
- **Base**: `main`.
